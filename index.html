Run commands from this project directory. The second command prompts for one value per line. A blank line or EOF finishes.

Sample values · Invalid-input example

The mathematical contract

J₀(x) = (1/π) ∫₀ᵖⁱ cos(x sin θ) dθ

Every implementation approximates this integral at 16,384 equally spaced midpoints. Inputs are restricted to −1000 ≤ x ≤ 1000.

NIST’s Bessel integral supplies the common definition. This is a numerical demonstration, not a certified special-function library.

Shared behavior

Inputs & arguments

PROGRAM [INPUT|- [OUTPUT [WORKERS]]]

Defaults: standard input, results.csv, two workers. Workers must be an integer from 1 to 16. Files and interactive input accept one decimal real per line, ignore # comment lines, and end at the first blank line or EOF. At most 4,096 valid values are accepted.

Native numeric parsers may accept additional literal forms. Decimal and scientific e notation are the common interchange format.

Outputs & failures

x,j0,worker_pid
0,1,12345
1,0.7651976865579666,12346

Rows preserve input order; the PID identifies the numerical worker. Invalid value lines are reported and skipped. Invalid arguments, empty input, I/O failures, and worker failures produce diagnostics and a nonzero exit. Output replaces the specified file after calculations complete.

Process IDs, decimal formatting, and final rounding vary by implementation. PIDs above are illustrative.

Goals & methodology

The aim is to compare how languages express the same work: ownership in Rust, relations in Prolog, conditions and restarts in Lisp, records and streams in Java, file statuses in COBOL, and structural matching in Python. The manifest records the full project description, goals, methodology, dependencies and constraints.

  1. Specify a shared input/output and failure contract before writing implementations.
  2. Use midpoint quadrature of the same integral with 16384 samples in every version.
  3. Choose native idioms and standard libraries; use a named dialect or OS extension when a language lacks process APIs.
  4. Use bounded process batches, or native process pools, preserving input order.
  5. Validate numerical answers against independent high-precision reference values, not just against another translation.
  6. Check invalid input, stdin, worker limits, file failures, empty input and argument misuse. Record unavailable toolchains as untested.
  7. Document SQL input/argument adaptations, process startup overhead, and floating-point differences.
  8. Keep unsafe memory demonstrations isolated; preserve allocation lifetime and bounds, then rerun the behavioral checks. Display an explicit memory/string feature map for every language.
  9. Use functional comments and purpose/input/output/caller contracts; use native block comments where available, # comments for Python, and ERA blocks for Perligata.

PostScript: preserving precision in the language

This edition keeps the existing 1e-10 absolute tolerance and implements all numerical work in PostScript, without a numerical helper or precision exception.

Ghostscript reals are single precision even in a 64-bit build. The nearest binary32 representation of J0(1) already differs by about 7.74e-9.

Signed 64-bit integers store fixed-point values with 52 fractional bits. Split 26-bit products, integer range reduction, Taylor cosine, decimal parsing/formatting and quotient/remainder summation preserve precision without native real arithmetic.

The same 16,384 midpoint samples are evaluated. Software arithmetic changes the representation, not the integral, domain, sample count or tolerance.

All scheduling is PostScript. Ghostscript %pipe% uses the POSIX shell only to exec the same interpreter via /proc/PID/exe; each child reads its own real PID from /proc/self/stat. No helper source in another language.

Run from the project directory with 64-bit Ghostscript, Linux /proc and -dNOSAFER for OS access. OS policies such as a printer-only AppArmor profile can still deny subprocesses or files. A different working directory requires -sBesselSource=/absolute/path/bessel.ps before --.

Input lines are bounded to 4096 bytes; longer lines fail with a readable diagnostic. Decimal input is parsed with less than 2^-52 + 1e-18 absolute truncation error.

gs -q -dNODISPLAY -dBATCH -dNOSAFER -- bessel.ps examples/values.txt results.csv 2

Open the commented PostScript implementation for the arithmetic and process contracts. The Ghostscript language reference documents native real precision and the pipe extension; this edition checks the required 64-bit integer support at startup.

SQL: a database-native edition

bessel.sql targets PostgreSQL with PL/pgSQL and dblink. Run it in a dedicated database. The script creates the extension if absent and temporary tables for the session. Each worker connection has a separate backend OS process; its numerical kernel is an aggregate over generate_series.

psql -X -d observatory -v values='0,1,5,10' -v workers=2 -v output=results.csv -f bessel.sql
# Interactive comma-separated input:
psql -X -d observatory -f bessel.sql
# Server-side file input:
psql -X -d observatory -v input=/absolute/server/path/values.txt -f bessel.sql

Connections must authenticate to the same database. An optional -v conn='service=observatory' selects a libpq service. File input uses pg_read_file on the database server and requires the corresponding permissions; CSV output is local to psql. Do not use --single-transaction, because worker connections must see the committed extension. PostgreSQL failures are reported by psql with ON_ERROR_STOP.

Comparison limits

  • This is a language study, not a process-startup benchmark: some versions reuse workers, others launch one child per value.
  • Runtime startup often costs more than the calculation; large JVM/BEAM runs are intentionally not optimized for throughput.
  • Error cleanup covers ordinary I/O and worker failures; signal handling is runtime-dependent. The examples do not promise transactional output under disk-full failures or process termination.
  • GNU Smalltalk must be launched from the project directory because its workers use the relative bessel.st path.
  • SQL requires a running PostgreSQL server; it cannot be executed as a standalone portable SQL file in SQLite/MySQL.
  • Use the supplied BASIC build helper: FreeBASIC generates a C intermediate, so compiling the same basename in the source directory can collide with the C edition.
  • Bash orchestrates the embedded awk numerical kernel because Bash arithmetic is integer-only.
  • Oberon-2 uses the supplied C adapter for checked OS and stdio interfaces; its quadrature and raw-address traversal are Oberon.
  • Perligata uses BesselPerligata.pm for regex validation, unchanged line reads, temporary storage and checked POSIX/exception services. Native perlege converts Roman numerals, so it cannot preserve this input contract. Opening/writing/closing files, quadrature and scheduling remain in Latin.
  • RPG requires IBM i setup described in rpg_setup.txt; failed or timed-out runs retain work rows, and submitted jobs may finish after parent failure.
  • Raw pointer arithmetic is unavailable in several listed languages; their native reference/offset models are documented instead.
  • PostScript retains the 1e-10 tolerance using software fixed-point arithmetic entirely in PostScript; Ghostscript native real arithmetic is too imprecise. It requires a 64-bit integer build.
  • PostScript requires Linux /proc and Ghostscript %pipe% access. Its POSIX shell only execs another interpreter; there is no foreign-language helper. Restricted printer-oriented OS profiles may block execution even with -dNOSAFER. Run from the project directory, or supply -sBesselSource before --.
